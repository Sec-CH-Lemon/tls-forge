правильно не создаёт wait. Фикстура проверки send/wait/receive теперь удерживает
оба ответа до наблюдаемого send event. Callback держит attempt mutex через
запись send и переход в wait: firstByte не может обогнать этот переход.

## Входная поправка ALPS observation

Стенд получил явный opt-in для пассивного приёма перед HTTP/2 reply. Его
включает fixture data только для ожидаемых отказов: writer освобождается
реальными HEADERS либо GOAWAY, без синтеза кадров. Это предотвращает
преждевременный server write до чтения терминального кадра. Клиентские
production policies, browser JSON и эталонные ALPS bytes не менялись.

Все первоначальные comparisons сохранены; адаптивные три replays удалены.
Теперь нужен правильный результат в единственном наблюдении. Положительные
HEADERS/GOAWAY и отрицательный silence control прошли10race повторов.

трёх профилей прошла под race42.250s, harness race suite35.512s/100%statements.

свежего native CI, и исходный Windows RED сохранён.
