# A10: отдельный браузер на запрос и профильные правила кэша

Дата:2026-10-30. Локальная реализация и приёмка A10 завершены.
Нативная CI-приёмка разрешена владельцем и выполняется следующим шагом.

Решение владельца2026-10-30 уточняет A10: каждый top-level запрос работает как
отдельный сетевой инстанс браузера. Это заменяет default shared pools A9.
Редиректы, preflight, authentication restart и protocol retries одного вызова
используют состояние этого вызова. Application retry CLI — новый вызов.

## Изменения

Стандартные18 JSON-профилей и83 catalogue entries явно выбирают
`http.instance_scope=request`. Каждый Do пересобирает DNS/QUIC state, TLS session
cache, пулы, cookies, HTTP auth, Client Hints, preflights и response cache.
Fresh пересобирает те же ресурсы. Явные cookie inputs отдельно seed каждый
инстанс; полученные cookies никогда не становятся входом следующего вызова.
Opaque jars и transport callbacks отклоняются до создания транспорта в request
scope: callback может скрывать общий jar/connection. Explicit client-scope JSON
описывает длительный workflow одного браузера. Старые browser sequence fixtures
выбирают этот scope явно; default isolation controls используют штатные профили.

Cache-Control сохраняет field lines, порядок, исходные сегменты и quoted-string
с escapes. Профиль выбирает first/stale, ignore/stale, принятие quoted delta,
лимит saturation, область кэша, набор валидаторов и относительный порядок
создаваемых полей. Прежние позиции полей в JSON layouts сохраняются. Полученные
ETag и Last-Modified могут добавлять оба условных поля. Frozen legacy JSON
не менялся; новые migration choices находятся в engine1 additions.

CLI экспортирует каждый cookie snapshot отдельно, включая cookies, полученные
до ошибки чтения тела. JSON sets не объединяются по proxy URL. Netscape output
с несколькими непустыми snapshots отклоняется до записи файла.
`--reuse-connection` и `--retry-as-browser` требуют explicit client-scope JSON.
`--fresh-connection` остаётся совместимым и избыточен в request scope.

## Браузерные измерения

Chrome156.0.8078.74/macOS27.0.1arm64, headed, фоновые свёрнутые окна, отдельный
user-data-dir на запуск. Две независимые когорты H1/H2, затем две H3.
34 стимула: прямой/обратный/одинаковый max-age, repeated lines, OWS/case,
quoted/escaped comma, invalid/negative/overflow, Expires/Age, no-cache/no-store,
ETag/Last-Modified/both и изменённое тело.

Один max-age600 — обязательный положительный hit control. Первоначальный запуск
с общим ignore-certificate-errors не давал этого hit и сохранён как отказ
trust precondition. Его cache результаты не использованы. Принятые когорты
используют явный SPKI trust для локального сертификата.

Измерено первое допустимое unquoted numeric значение без OWS вокруг `=`.
Invalid/negative/quoted значения пропускаются, допускается следующий валидный
max-age либо Expires. Huge decimal saturates и даёт hit в описанном сценарии.
Точный предел4294967295 не установлен finite samples: он унаследован из
Chromium parsing uint32. Использованный официальный main blob
242c34edcfc8b3759dc82f2a14aff863158fb822 не объявляется исходником точного156tag.
Дубликаты и invalid freshness не являются безусловными нарушениями MUST:
см.[RFC9111](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2.1).

H1/H2: исходный B0 совпал в64/136 парах, кандидат в136/136 по origin count,
API status/body, значениям и полному порядку request headers.
H3: исходный B0 совпал в32/68, кандидат68/68 по тем же критериям; все реальные запросы HTTP/3.0.
Финальный воспроизводимый общий прогон: B0 **96/204**, кандидат **204/204**.
Server qlog сохраняет порядок после QPACK decode. Первоначальный observer
с неверным pointer assertion дал пустой журнал; он сохранён, приёмка порядка
повторена новым observer. Нормализация — только loopback origin host/port
в Host/:authority и origin-prefix в Referer; path и все прочие поля сохранены.
Raw QUIC datagrams, key logs, CDP, Chrome NetLog, исходные заголовки и API
результаты остаются приватными. Это не приёмка совпадения QPACK scheduling.

## Границы

Engine остаётся одним unpublished1.0.0/schema4/daemon3/SDK1.0 candidate,
anchor published0.2.2. Нового major до публикации не требуется.
[Инвентарь A10](../../../profile/provenance/a10.json) связывает новые JSON SHA,
исходные B0 SHA и происхождение каждого нового поля. A8 acceptance.json
сохранён как историческая приёмка исходных байтов; новые поля не получают
автоматически её native Linux/Windows verdict. Older builds и другие платформы
наследуют156macOS rules с явной пометкой. Generated range positions не были
переизмерены в A10. Нет нового доказательства WAN/proxy/kernel/TCP/ECN/GSO,
полной indistinguishability, RNG distribution или resumed/0RTT equivalence.
Тула моделирует сетевое поведение и не запускает JavaScript/browser process.

## Воспроизведение

Собрать `scripts/a10-cache-client.go` и `scripts/a10-h3-peer.go` отдельными
Go commands. Подготовить private certificate/key и отдельный JSON-profile,
отличающийся от chrome_156_macos только `behavior.http.instance_scope=client`.
Это явный input same-browser эксперимента, а не значение shipped default.

```sh
node scripts/a10-cache-observe.mjs --out PRIVATE/chrome --actor chrome \
  --chrome CHROME_BINARY --build 156.0.8078.74 --cert CERT --key KEY \
  --scenarios scripts/a10-cache-scenarios.json --protocols h1,h2,h3 --peer H3_PEER
node scripts/a10-cache-observe.mjs --out PRIVATE/client --actor client \
  --client CLIENT_ACTOR --profile SEQUENCE_PROFILE --cert CERT --key KEY \
  --scenarios scripts/a10-cache-scenarios.json --protocols h1,h2,h3 --peer H3_PEER
python3 scripts/a10-cache-compare.py --chrome PRIVATE/chrome --client PRIVATE/client \
  --scenarios scripts/a10-cache-scenarios.json --out PRIVATE/comparison.json
```

Output directories должны быть новыми и приватными. Сводка без raw secrets:
[204 пары и negative controls](checks-a10-browser.json).

Машинная сводка локальных проверок: [A10 local checks](checks-a10-local.json).

Приватный архив `../net-fp-server/captures/tls-forge-a10-20261030/evidence.tar.gz`: SHA-256
`aef5c2447426837cc378493b3d88fea18c4fe5ad9bcf61a5b1bae70d739be15f`; 4780 записей, каждый regular member
проверен по отдельному SHA manifest. Исходные before/after, все RED, raw
Chrome/QUIC/key logs и их нормализация сохранены; секреты в Git не попадают.
