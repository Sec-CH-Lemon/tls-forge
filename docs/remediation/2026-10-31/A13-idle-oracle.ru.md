# A13: единицы длительности QUIC idle close

Принято локальное исправление тестового oracle. Runtime, JSON-профили и
параметры таймеров не менялись. A13 и оценщик сети этим не закрываются.

Полный прогон R08 сохранил отказ
`TestAQUICClientProbesSilenceAndClosesAsChromeDoes`: аутентифицированный
CONNECTION_CLOSE содержал `1005ms`, тогда как регулярное выражение требовало
только `us`. Пакеты, их номера, два probe и код закрытия прошли свои проверки.
Отказ не заменён удачным повтором: исходный полный JSONL сохранён.

Независимый первичный источник —
[QuicTime::Delta::ToDebuggingValue](https://quiche.googlesource.com/quiche/+/a1628192cf32ba40d21e0dd80f485d68c24ff87a/quiche/quic/core/quic_time.cc),
revision из DEPS Chrome156.0.8078.76. Он выбирает `s` при точной кратности
секунде, затем `ms` при кратности миллисекунде, иначе `us`. Это источник
правила форматирования, не новый замер браузера.

Oracle теперь дополнительно разбирает длительность, требует диапазон от1s
до1300ms данного сценария и каноническую единицу. Не допускаются дроби,
ведущие нули, overflow, посторонний текст, изменённые timeout, prefix и
undecryptable state. Существующие wire-проверки probe timings, номеров пакетов,
кода закрытия, отсутствия лишнего coalescing и самого закрытия сохранены.

На опубликованном графе зависимостей прошли10 заранее заданных повторов под
race:20 тестовых запусков, без отказов. Два отдельных мутанта — разрешение
неканонической единицы и удаление границ длительности — пойманы неизменными
детерминированными controls. Никаких адаптивных повторов в тесте нет.

[Машинный отчёт](checks-a13-idle-oracle.json) закрепляет source hashes,
полный исходный отказ, after-проверки и новый приватный immutable capsule.
Публикация каталожных зависимостей, итоговый root gate каталога, F03 C–E
и native A13 CI остаются отдельными критериями.
