# A13: имя профиля и внутренний ID uTLS

Этот атомарный фикс закрывает один воспроизведённый дефект проверки F02/D.
A13 в целом, материализация каталога F02/C и estimator F03 A–E ещё открыты.

До исправления `ClientHelloID.Client` получал `Profile.Name`, а версия — `0`.
В uTLS строки `Golang-0`, `CustomInternal-0` и три `Randomized*-0` имеют
специальное исполняемое значение. Поэтому переименование неизменённого
schema4-профиля могло заменить профильный handshake на другой механизм,
несмотря на заданный `SpecFactory`. На исходном024e5c91 новая проверка
воспроизвела пять отказов; контрольные `Chrome` и `neutral` прошли.

Adapter теперь получает постоянный внутренний ID `tls-forge-profile-0`.
`Profile.Name` и User-Agent остаются метаданными; выбранный TLS factory
определяется данными профиля. Параметры TLS, JSON browser values, порядок
shuffling и обязательная проверка engine major сохранены. Это механизм
adapter, а не перенесённая в Go browser policy. Следующий engine major не
резервируется повторно: текущий1.0.0 ещё не опубликован.

Постоянная проверка строит настоящий сериализованный ClientHello без сокета
для семи имён и сравнивает его с неизменённым156/macOS fixture по существующему
строгому manifest. Она проверяет данные и ошибки, не внутреннюю строку ID.
Исходные raw bytes до/после сохраняются отдельно. Полный source export с
единственным runtime fix прошёл23/23 пакета без кэша, каждое утверждение
coverage покрыто; lint дал0 замечаний. [Машинный результат](checks-a13-identity.json).

Ограничения: это не новая когорта реального Chrome, не перенос83 каталожных
entries в JSON и не исправление сетевых hints. Старые schema0–2 migration
rules имеют отдельный compatibility contract; этот фикс не объявляет их
эвристику поведения новой browser acceptance. Более поздний TLS descriptor
кандидат проверяется отдельно и не входит в исходники этой приёмки.
