# A8: нативная приёмка и устойчивость измерений

> Промежуточный отчёт этапа; итоговая приёмка и ограничения: [A8](A8.ru.md).

Приёмка ещё продолжается. Три профиля156 не назначены новыми defaults.

Первый полный нативный run40928528624: headed capture/compare прошли на
macOS, Linux и Windows; все существующие fixtures прошли на Linux. На macOS
один flow-control update не совпал с half-window fixture, на Windows три
mixed-form POST redirect сценария дали0 запросов. Локальный macOS полный
fixture run прошёл. Исходные отказы сохранены; assertions не менялись.

Точечные повторы40944006789/macOS и40944010919/Windows прошли. Второй
macOS40944574439 прошёл; Windows40944578652 снова дал0 запросов по всем
шести H1/H2 проверкам. Один успешный повтор не устранил это расхождение.

Найден дефект тайминга harness: settled-сценарий ждал4s с запуска процесса,
так что медленный запуск мог занять всё время наблюдения и закончиться как
успешная пустая выборка. Барьер теперь ждёт первый запрос начальной страницы
в пределах прежнего startup limit, затем отсчитывает исходные4s. Ожидаемые
запросы/заголовки, сценарии, settle и сравнение не меняются. Медленный запуск
отдельно воспроизведён тестом: RED до исправления; полный пакет harness PASS
31.571s,100%; три race-повтора целевых проверок PASS2.227s. Нативный повтор
с этим исправлением остаётся обязательным.

H3: первые полные кампании отвергнуты при дополнительном соединении; ни один
такой случай не исключался из выборки. Постоянная вкладка проблему не решила.
Chrome NetLog показал создание cert verifier и MARK_ALL_ACTIVE_SESSIONS_GOING_AWAY
сразу перед разделением последовательности; рядом шли component/CRLSet updates.
[Закреплённый Chromium156 исходник](https://chromium.googlesource.com/chromium/src/+/156.0.8078.74/net/quic/quic_session_pool.cc)
явно выводит сессии из пула при OnCertVerifierChanged. Контроль со стандартным
для fixture harness --disable-component-update прошёл две независимые Chrome
когорты по512 соединений. Проверки кардинальности сохранены. Изменение trust
store во время последовательности не входит в фиксированный сценарий A8.

Предварительные48 соединений дополнительно проверены независимым TShark4.6.9:
1267 оригинальных UDP datagrams,224 потока побайтно совпали с observer output;
отсутствие TLS keys и удаление клиентских application packets отвергнуты.
PCAP использует синтетические IPv4/UDP headers, payload неизменён. Это не
доказательство свойств IP/kernel/ECN/GSO. Полные нативные кампании должны пройти
отдельно вместе с ls-qpack0.3.23 и заранее заданной статистикой GREASE.


## Полная H3 приёмка

Две Chrome-когорты и две Client.Do-когорты по512 соединений плюс held-SETTINGS
контроли приняты на macOS27, Linux и Windows:6240 соединений,18720 запросов.
На каждом хосте C ls-qpack0.3.23 подтвердил декодирование и точные raw QPACK/
control shapes внутри наблюдённых состояний. Никаких нормализаций заголовков
или encoder-stream bytes нет. Частоты статической/динамической первой секции
различаются у акторов и не объявлены равными. Все заранее заданные16-bin
Pearson и browser/client two-sample scores ниже60. Полный диапазон uint32
установлен исходником quiche, не выводится из конечной выборки.

Независимый TShark4.6.9 восстановил по10384 потока на каждом основном хосте:
macOS56739, Linux43486, Windows45960 оригинальных UDP datagrams. Все байты
совпали с отдельно сохранённой записью peer; missing-key и removed-client-
application controls отвергнуты. Дополнительный hostedmacOS run40947165721
прошёл producer и независимый C oracle,2080 соединений отдельно. Главные
Linux/Windows данные — успешные jobs run40946185950; общий run красный из-за
раннего macOS cleanup ENOTEMPTY, исправленного с ограниченными повторами
в53ebacc2. Исходный отказ не считается сетевым verdict и сохранён.

Хеши и статистики: [checks-a8-native-h3.json](checks-a8-native-h3.json).
Официальные установщики закреплены SHA256. Linux .73 и macOS/Windows .74
используют одну quiche a1628192cf32ba40d21e0dd80f485d68c24ff87a. У замороженной
локальной macOS копии все388 записей официального .74 bundle идентичны;
316 дополнительных файлов относятся только к неактивной .48. Current symlink
указывает на .74. Проверки подписи и полный file inventory сохранены отдельно;
криптографическое происхождение исполняемых байтов здесь установлено точным
сравнением с официальным DMG, а не успешным codesign strict.

Не измерены: WAN/kernel/TCP/ECN/GSO, resumption/0RTT, произвольные origins,
blocked/malformed H3/error policies и полный browser fingerprint. Нативные
fixtures и финальный QA остаются отдельным условием завершения A8.


Приведённые выше когорты относятся к состоянию **до** нижнеграничного
исправления placement. Все реально наблюдённые N>0 совпали в заданном scope;
это не доказательство правильного размещения при N=0. Первичный
HttpEncoder::SerializeSettingsFrame сортирует ID; дополнительный реальный
wire-контроль N=0 выявил порядок1,6,7,51,33 вместо1,6,7,33,51. Исходный RED
сохранён отдельно, JSON-примитив и повторная приёмка идут следующим срезом.


## ALPS readiness repair

Полный run40947160403 прошёл остальные группы, но остановил ALPS на
accept-ch-flags: новый общий startup-барьер ошибочно требовал HTTP-запрос и
для сценария, где исходная fixture ожидает PROTOCOL_ERROR/GOAWAY до HTTP.
Это регрессия самого измерителя, а не новый browser/product verdict.

Теперь обычные request-сценарии ждут начальную страницу, ALPS-сценарии —
фактически записанный handshake. Затем действует исходный settle. Пустой
процесс не считается отвергнутым handshake. Никакие ожидаемые GOAWAY,
handshakes или запросы не менялись. Реальный TLS/H2 peer с SETTINGS и GOAWAY
без HEADERS воспроизводит RED на архиве; после исправления три race-повтора
PASS2.322s, полный harness PASS33.642s100%. Нативная ALPS-группа повторяется
целиком; исходный полный обход остальных групп сохраняется отдельно.
