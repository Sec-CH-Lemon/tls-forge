# A8: явная основа кандидата capture

> Промежуточный отчёт этапа; итоговая приёмка и ограничения: [A8](A8.ru.md).

Завершена часть C04/F02B в API/CLI. Общая A8 ещё не принята: workflow,
GREASE и нативные профили Chrome156 трёх платформ проверяются отдельно.

До исправления сборщик терял данные основы: на сохранённом исходном дереве
156d99fa получено203 ключа вместо340. Исходный RED и архивы root/четырёх
форков сохранены. Прежнее предположение плана про close_notify=true в этой
точке не воспроизвелось: оба значения былиfalse; доказанный дефект — потеря
полной политики, а не это конкретное значение.

Теперь FromCapture требует полную явную schema4/engine1 основу, сохраняет
все неизмеренные ключи и правила генерации. Имя/UA/бренды не выбирают
поведение. CLI выбирает только явно поставляемую основу той же семьи/платформы
либо --policy-from; отсутствие/неверный major отклоняются до измерения.
Новые --policy-from и --provenance-dir описаны в README и документации API.
JSON с сохранением остаётся одним документом вstdout, прогресс идёт вstderr.

Отдельный provenance содержит SHA256 точных сохранённых байтов профиля,
канонические JSON-хеши основы/захвата, режим запуска и происхождение полей.
Контекстные наблюдения не превращаются в новые константы; неизмеренные
значения основы остаются inherited. Метаданные не исполняются как профиль;
выход через symlink проверен подos.Root.

Проверки: profile PASS11.195s,100% statements; целевые CLI сrace PASS55.585s;
фактический TLS/H1/H2 путь сrace PASS2.069s,4 одновременно живущие политики
закрытия после capture→Save→Load→Client.Do. Есть отрицательные проверки
отсутствующей основы, неверного major, подмены имени/UA, потери происхождения,
выхода метаданных за корень и несовместимых наблюдённых генераций.

Хеши исходных доказательств: [checks-a8-capture.json](checks-a8-capture.json).
Приватные оригиналы: captures/tls-forge-a8-20261029 в соседнем net-fp-server.
Унаследованная политика не получает нового browser-verdict; полный QA
модуля и workflow-интеграция выполняются следующими частями A8. Engine остаётся
единым неопубликованным1.0.0; профили заново не ретегируются.


## Workflow integration

capture.yml теперь вызывает тот же CLI builder и сохраняет отдельный
capture-provenance_<profile> artifact. Drift проверяет точные байты, major,
схему и inherited происхождение всех policy keys; метаданные не копируются
в profile/data. По актуальному owner-контракту development-only workflow
предлагает проверенные artifacts без создания profile/* веток и PR.

Для A8 добавлен browser=156: официальные Google установщики .73/Linux и
.74/macOS/Windows закреплены полными SHA256. Их оригиналы и ответы updater
сохранены приватно. Полная установленная версия проверяется до измерения;
текущий Stable157 не может быть незаметно принят как156. Headed compare
отделён от существующего headless fixture harness measure --check --newer.
H3/QPACK требуют своей отдельной приёмки.

Pinned run требует публичный evidence-certificate. Capture JSON и исходные
fixture logs сохраняются только как CMS-encrypted artifacts, приватный ключ
остаётся локально под ignored captures. Локальный encrypt/decrypt roundtrip
прошёл побайтовое сравнение. Отрицательные тесты проверяют изменённый
установщик, иной URL/hash/version, изменённые profile bytes, неверный major,
отсутствующее provenance и ложную отметку measured. actionlint и
make workflows-check проходят. Нативный CI после публикации ещё не запускался.


## Full race follow-up

Первый полный race-прогон immutable export a8846b3 прошёл root и остальные
пакеты, но завершился RED в CLI TestAProfileIsFiledUnderTheBrowsersPlatform.
Старая фикстура меняла только Navigator UA, оставляя desktop UA в фактических
H1/H2 заголовках. После C04 wire UA является источником истины; фикстура
исправлена согласованно в обоих протоколах и теперь отдельно требует явной
основы для непоставляемых mobile/ChromeOS платформ. Три целевых race-повтора
прошли4.035s. Исходный полный RED сохранён; это ещё не полный зелёный прогон.


## Capture failure-path acceptance

Полная свежая coverage-проверка после фикстуры прошла функциональные тесты
всех пакетов, но строгий gate сохранил RED: новый CLI был99.6%.
Негативные I/O проверки выявили необходимость готовить и проверять provenance
до замены прежнего профиля. Теперь повреждённые capture/H2/extra JSON,
недопустимый --set и отказ открытия metadata root не заменяют старый файл.
Повторная проверка сохранила прежний отказ отсутствующему parent file-save:
создание metadata не должно делать этот destination автоматически доступным.
Первый промежуточный отказ TestCaptureErrors сохранён; проверку не ослабляли.

Три целевых race-повтора PASS21.728s; полный CLI PASS55.972s и100% statements;
lint0issues. Удалены лишь недостижимые дубли validate/relative-path errors:
Registry.Get уже валидирует все пути, destination теперь строится как
root+relative. Provenance конструктор сериализует/клонирует весь raw JSON до
форматирования; неизвестные/bad JSON ошибки остаются проверены до записи.

Профиль и отдельное provenance пишутся каждый атомарно; общего filesystem
transaction для двух разных destinations нет. Ошибка финальной metadata
записи возвращается явно и не означает browser acceptance. При внешнем
чтении пары всегда проверяется точный SHA профиля.


Пустой объект HTTP1 без полей и порядка не считается наблюдением: builder
сохраняет явную основу, provenance помечает её inherited. Регрессионный
тест на архиве b6dafd53 падает, после исправления пакет profile проходит
с покрытием100% (13.635s). Исходный RED сохранён отдельно.
