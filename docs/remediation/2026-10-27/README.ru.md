## A0a: исходный снимок

Сохранены полные Git-архивы основного модуля и пяти транспортных форков,
коммиты и деревья, хеши модулей, исходных доказательств и согласованного плана.
Исходники всех шести репозиториев совпадают с коммитами аудита; tracked diff
пуст. Посторонние неотслеживаемые файлы исходного каталога не включены ни в
снимок исполняемых исходников, ни в коммит.

Приватные архивы, оригинальные журналы и точные команды сохранены в
`net-fp-server/captures/remediation-a0a-20261027`. Они не публикуются в Git.
Безопасные исходники предоставленных PoC сохранены рядом с манифестом:

- [HPACK](a0a/hpack-quadratic-poc_test.go.txt);
- [слои Content-Encoding](a0a/content-coding-stack_test.go.txt);
- [PSK + HRR](a0a/psk-hrr-main.go.txt);
- [заголовки редиректов](a0a/redirect-header-leak_test.go.txt);
- [пулы, прокси и редактирование ошибок](a0a/root-runtime-defects_test.go.txt).

Сборка и каждый запуск изолированы в отдельном процессе. Внешний
[контроллер](a0a/bounded-runner.py.txt) ограничивает время и суммарный RSS
группы процессов; при превышении завершает всю группу. Жёсткий лимит RSS
1,5 ГиБ, лимит воспроизведения 90–180 секунд; фактические значения и пики
записаны в манифесте. Использован Go 1.26.10 darwin/arm64. Это ограниченное
воспроизведение на собственных локальных peers, не новая браузерная приёмка.

| S10 | Второй пробрасываемый запрос не достигает транспорта, пока первый 700 мс ждёт ответа |

Предоставленные PoC наблюдательные: их `PASS` подтверждает выполнение
эксперимента, а не отсутствие дефекта. Остальные отрицательные сценарии S01–S10
будут превращены в регрессионные проверки перед соответствующим исправлением.
Исторические browser verdict не переназначены этому снимку.

Удалённый тег `v0.2.2` подтверждён по SSH; тега `v1.0.0` нет. API релизов вернул
HTTP 401, поэтому факт публикации независимо через него не установлен.
Используется подтверждённый владельцем якорь `0.2.2`; кандидат остаётся
`1.0.0 / engine_major: 1`. Удалённый тег сам по себе не объявлен публикацией.

## Порядок дальнейшей работы

После A0a идёт A1: S01 (HPACK, CONTINUATION, чанки) и S04 (редиректы).
Затем A2–A5 в согласованном порядке. Изменения runtime, тесты и профильные
данные ещё не внесены. A0b не является условием начала P0. Каждый исправленный
контракт будет иметь отдельное доказательство до/после и атомарный коммит.
