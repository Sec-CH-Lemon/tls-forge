## S03: PSK + HelloRetryRequest

utls `281f37fda04188b3fe886fd58c09ddcdec13c8fe` пересчитывает binder после
сериализации настоящего профильного ClientHello2, с транскриптом
message_hash(CH1)||HRR||Truncate(CH2). Данные браузера не менялись. Очищается
cached length PSK при его снятии из-за несовместимого hash. Неизвестная opaque
PSK implementation получает явный отказ вместо неподходящего binder.
Настоящий ECH `helloRetrySpecECH` остаётся отдельным неизменённым путём.

На одних native crypto/tls peers (P-256/P-384-only и X25519 control) выполнены
три шестизапросные серии на каждый вариант. До исправления: 18 отказов из54,
15 сервером подтверждённых resumption. После: 54/54 успешны, 45 resumption.
Root regression проверяет шесть новых соединений на каждом curve и требует
DidResume на2–6; простой успех полного handshake его не удовлетворяет.
Тот же контроль добавлен в сам utls. Полный utls suite и целевые race-тесты
проходят, в том числе pinned `GOWORK=off` в основном модуле.

Chrome156.0.8078.48/macOS arm64: девять независимых headed/minimized контекстов,
54 запроса, 36 resumption. Первая navigation и следующий fetch используют
разный контекст TLS-кэша: запрос2 ещё полный,3–6 возобновляются. Это различие
с API-серией не объявляется совпадением общего lifecycle/NIK. Сравнение CH2
проводится отдельно по cold/resumed состоянию, не по порядковому номеру запроса.

36 Chrome и36 candidate HRR: совпали полный статический состав и векторы CH2,
правило сохранения extension order/random/session ID/GREASE ECH внутри пары,
замена key_share и пересчёт PSK. Между соединениями extension order перемешан;
сравнивается multiset с сохранением данных. GREASE codepoint нормализуется
точечно в cipher/group/version/signature_algorithm/extension векторах.
Исходный comparator failure до учёта signature GREASE сохранён; mutation
обычного signature algorithm отвергается. Это не проверка распределения RNG.

Независимый Python HMAC/HKDF oracle вычисляет binder по оригинальным
CH1/HRR/CH2 и server-issued secret. Все binders корректны; отдельно ломаются
CH1, HRR, CH2 и отсутствие message_hash. Проверены также actual peer
DidResume и полный raw-handshake multiset: исходные bytes всех504 сообщений
из pcap совпадают с socket transcripts. Повторяющиеся ключи JSON tshark сохраняются; обычный
last-key-wins разбор терял144 сообщения и был отвергнут. HTTP расшифрован
непосредственно из исходного pcap с отдельным keylog. Original pcap не менялся,
потерь tcpdump —0; TLS secrets остаются только в ignored captures.
