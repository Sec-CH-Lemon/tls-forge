## Что изменено

Release-конвейер приведён к принятому CI: обычные Go-тесты выполняются на
трёх ОС; полный root race разделён по обнаруженной компилятором inventory,
остальные пакеты исполняются целиком. Лимиты сохранены: 20m на race binary,
10m на normal binary и 40m на Go job. Независимый manifest gate обязателен перед
storage/publication. Порог покрытия остаётся 100% каждой функции.

CHANGELOG оформлен как явно неопубликованный `1.0.0`. Полный исходный
[development journal](1.0.0-development-history.md) сохранён с SHA-256
`28bd98b1f0b861aad055c9c320b1a864c9647f690624f1dbc048963b045ffead`.
По разрешению владельца 146 tracked исторических документов перенесены
из `docs/` в `research/`; исходные перемещения проверены побайтно.
Публичные references генерируются из исходников, strict MkDocs и rendered
links проверяются в обоих конвейерах. Python defaults сохраняют source
expressions, включая `sys.platform`, вместо платформы сборщика.

Устранены только подтверждённые препятствия приёмки:

- Python write-timeout fixture дожидается offline readiness и доказывает живую
  blocked writer. Исходные 0.2s deadline, elapsed bound, cleanup и recovery
  assertions сохранены; runtime SDK не менялся.
- Строгий oracle получает availability network hints из реального выбранного
  JSON estimator вместо старого literal-only lookup. Добавлены проверки
  syntax/range/quantum/ECT; raw values и политика нормализации сохраняются.
  Исходный `internal/harness/compare.go` неизменён.
- JSON-only full-version hints обновлены к измеренным Chrome 156 builds;
  шесть прежних профилей сохранены точно, derivations добавлены отдельно,
  оригинальные A13/capture hashes не переписаны. Engine major не менялся.
- Windows oracle двух auth-сценариев откалиброван в двух независимых native
  когортах. Остальные 226 сценариев и исходный macOS fixture неизменны.
  Ни один сценарий не исключён; поддержка auth в продукт не добавлялась.
- fhttp `f88cd25` исправляет подтверждённую потерю preface PING при быстром
  ответе во время HEADERS Write. Решение принимается до I/O, отдельный PING
  отправляется после HEADERS. JSON timers/IDs и исходные wire assertions
  неизменны. Публичная зависимость закреплена без local replace/go.work.
- Proxy body-limit fixture читает точное полное тело 413 до закрытия caller и
  server. Native coverage profiles теперь сохраняются и при отказе. Runtime
  proxy, его лимит и порог покрытия не менялись.

Исходные RED, before/after, source archives и negative controls сохранены.
Для proxy старый native job не сохранял `coverage.out`; воспроизведён
соответствующий дефект предусловия и дефицит одной инструкции, но точная
missing строка того runner остаётся неизвестной. Итоговая полная native
приёмка прошла без снижения требований.

## Chrome: что именно принято

Google Stable 156.0.8078.79 на Linux/amd64 и 156.0.8078.80 на
macOS/arm64 и Windows/amd64. Во всех трёх cold comparisons пусты TLS,
HTTP/1.1 и HTTP/2 differences. Полные исходные browser/client projections
сохранены вместе с результатом.

В каждом native запуске реально выполнены 228 сценариев по H2 и H1
(456 последовательностей) и 174 декодирования. Progress logs независимо
сверены с полными source fixtures. Windows имеет собственный точный oracle
только для двух SSPI-сценариев, без `Apart` или новых normalization exclusions.
Это browser-versus-fixture проверка; она не доказывает выполнение NTLM
движком. Холодный transport comparison отдельно использует настоящий клиент.

Во всех трёх успешных результатах сохранены по 10 observations/30 raw
RTT/Downlink/ECT fields. Все 90 полей независимо проверены точной decimal
арифметикой по JSON syntax/bounds/quanta/labels, с отрицательными controls.
Значения физической сети не объявлены равными: существующая нормализация
явно записана. Качество RNG и полное распределение этим не доказаны.

PING дополнительно проверен на настоящем Chrome 156.0.8078.80/macOS 27.0.1:
две независимые когорты по три запуска, warmed connection, fetch после
11s idle. Все шесть сохранили H3→P1 на той же connection. Первый cold socket,
закрывшийся до idle fetch, сохранён отдельно и не включён в этот verdict.
Старый root test побайтно неизменён; 48 локальных race runs и оба полных
fhttp graphs по 1911 runs приняты. Это конечная проверка данного состояния,
не статистическое доказательство всех WAN/backpressure вариантов.

## Ограничения и дальнейшая публикация

- NTLM/Negotiate в продукте не реализованы. Владелец явно выбрал завершить
  подготовку 1.0.0 без этой новой auth-возможности. Windows fixture измеряет
  Type1, не завершённую Type3/Kerberos authentication.
- Приёмка относится к указанным Chrome 156 builds, платформам, сценариям и
  исходникам. Исторические/другие executable profiles не получили новую
  глобальную browser-equivalence оценку. Ядро ОС и TCP fingerprint не заменены.
- Сохранены прежние platform skips fork suites: uTLS 1, fhttp 36, QUIC 3,
  tls-client 6 unique skips на graph. Новых failure allowances/exclusions нет.
- Прежние явно описанные Chrome/RFC отклонения ACK и TLS close_notify не
  переобъявлены соответствующими всем стандартам. Выбор владельца и отдельные
  close_notify профили сохранены. Старые необъяснённые timing observations
  не объявлены исправленными новым PING patch.
- Dry-run подтверждает сборку, проверки и readiness набора; publication jobs
  намеренно не исполнялись. Для реального релиза требуется отдельное разрешение
  владельца. Тег/повторная сборка должны назвать точный принятый source; нельзя
  переименовать набор `51918c0` в артефакты более нового HEAD.

Raw evidence хранится приватно в collector captures:
`tls-forge-release-1.0.0-20261101/R26/`, отдельные immutable capsules
`PREPARATION`, `STRICT-BEFORE`, `WINDOWS-ORACLE`, `PING-LOCAL`, `PROXY-LIMIT`
и `FINAL`. TLS secrets/сырые capture archives в Git не добавлены.
